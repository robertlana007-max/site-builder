What is Base64 Encoder / Decoder?

The Base64 Encoder / Decoder turns normal text into Base64 and turns Base64 back into normal text. Base64 writes any data using only letters, digits, plus (+), slash (/) and the equals sign (=), so it can travel safely through systems that only accept plain text.

It is useful for developers, system admins and students who meet Base64 in API headers, email source, data URLs, JSON Web Tokens or config files. Use it when you see a long string ending in = and want to know what it says, or when a system asks you for a Base64 value.

The text is converted in your browser and is not sent anywhere. Text is handled as UTF-8, so accented letters, other scripts and emoji work correctly.

What you can use it for

Read a Base64 value

Decode a string from a log, a header or a config file to see the original text.

Create a Basic Auth value

Encode text like user:password to build the value for an HTTP Basic Authorization header while testing.

Inspect part of a token

Paste the middle part of a JSON Web Token and click “Decode from Base64” to read its claims. URL-safe Base64 is accepted.

Store text safely in config

Encode text that contains quotes or line breaks so it fits inside a single config value or environment variable.

Learn how Base64 works

Encode short words and compare the input and output to see how 3 bytes become 4 characters.

Step-by-step tutorial: how to use Base64 Encoder / Decoder

  1. Type or paste your text

    Click in the “Text or Base64” box and paste what you want to convert. The same box is used for both input and output.

  2. Click “Encode to Base64”

    Click “Encode to Base64” to convert the text. The box now shows the Base64 result on one line and the message says “Encoded.”.

  3. Or click “Decode from Base64”

    If the box holds Base64, click “Decode from Base64”. The box now shows the original text and the message says “Decoded.”.

  4. Paste URL-safe or unpadded Base64

    When decoding, you can paste the URL-safe form that uses - and _ instead of + and /. Missing = padding at the end is added for you, and spaces and line breaks are ignored.

  5. Copy the result

    Click “Copy” to copy everything in the box to your clipboard.

  6. Clear the box

    Click “Clear” to empty the box and the message before you convert something else.

Features

  • Full UTF-8 supportText is turned into UTF-8 bytes before encoding, so “café” and emoji encode and decode correctly.
  • URL-safe inputDecoding accepts both the standard alphabet and the URL-safe alphabet used in JWTs and web links.
  • Forgiving decodingSpaces, line breaks and missing = padding are handled automatically when you decode.
  • One box, two directionsEncode and decode in the same box, so you can switch back and forth quickly.
  • Clear status messagesYou see “Encoded.”, “Decoded.” or a clear error message under the buttons.
  • Copy and Clear buttonsCopy the result in one click, or clear the box to start again.

Worked example: encoding and decoding a greeting

Type Hello, World! in the box and click “Encode to Base64”. The box now shows SGVsbG8sIFdvcmxkIQ==. The 13 characters of input become 20 characters of Base64, and the two = signs at the end are padding. Click “Decode from Base64” and the box shows Hello, World! again. With non-English text, the word café followed by a space and the coffee cup emoji encodes to Y2Fmw6kg4piV, because é and the emoji each take more than one byte in UTF-8.

Tips and tricks

  • Base64 output is about one third longer than the input. Every 3 bytes become 4 characters.
  • Encoded output is always one single line with no line breaks, which is what most APIs and config files expect.
  • If you encode something twice by mistake, click “Decode from Base64” twice to get back to the start.
  • A trailing space or line break in the input changes the Base64 output. Check the end of your text if a value does not match.
  • For JWTs, decode only one part at a time, the text between two dots. The whole token with dots is not valid Base64.
  • You can paste a whole data URL such as data:image/png;base64,... and click “Decode from Base64”. The data:...;base64, part is skipped and the image is offered as a download.

Problems and how to fix them

“That is not valid Base64.”

The box contains characters that are not in the Base64 alphabet, such as dots or other symbols, or a character is missing. Remove the extra characters, or decode one part of a JWT at a time.

“This is valid Base64, but it holds binary data, not text”

The Base64 holds a file, such as an image or a PDF, rather than text, so it cannot be shown in the box. Click the “Download decoded” button that appears to save the bytes as a file. Common types like PNG, JPEG, GIF, PDF and ZIP get the right file extension.

The result is the wrong text

You may have clicked encode when you wanted decode. Click “Decode from Base64” to undo, or click “Clear” and paste again.

Another tool gives different Base64 for the same text

Check for invisible differences, such as a trailing line break or a different character encoding. This tool always uses UTF-8.

Questions and answers

What is Base64 used for?

It turns any data into plain letters and digits so it can travel safely in places that only accept text, such as email, JSON and data URLs.

Is Base64 encryption?

No. Anyone can decode it. Do not use it to hide passwords or secrets.

Does it support URL-safe Base64?

Decoding accepts both the standard and URL-safe alphabets, with or without padding.
