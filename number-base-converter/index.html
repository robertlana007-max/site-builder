What is Number Base Converter?

The Number Base Converter changes numbers between binary, octal, decimal, hexadecimal and any base from 2 to 36. It handles very large numbers exactly, negative numbers and numbers with a fractional part.

It also shows the two's complement bit patterns for 8, 16, 32 and 64 bits and explains the conversion step by step with the division method, so it suits computer science students, programmers and electronics hobbyists.

All conversions run in your browser.

What you can use it for

Computer science homework

Convert between binary, octal, decimal and hex and follow the division and multiplication steps.

Programming

Check hex colour values, bit masks and memory addresses, including 0x and 0b prefixes.

Two's complement

See how negative numbers are stored in 8, 16, 32 or 64 bits, or decode a bit pattern like FF as a signed number.

Fractions in binary

Find out why 0.1 cannot be stored exactly in binary: it repeats as 0.0(0011).

Unusual bases

Convert to base 3, base 7 or base 36 for puzzles and short codes.

Step-by-step tutorial: how to use Number Base Converter

  1. Type the number

    Enter it in the Number box, such as 255.625, −42, 1011.01 or FF. Spaces and underscores between digits are ignored.

  2. Say which base it is in

    Pick Decimal, Binary, Octal, Hexadecimal or Other base. A prefix like 0x, 0b or 0o sets the base automatically.

  3. Read the results

    Binary (grouped in fours), octal, decimal and hex appear at once, and the last row converts to any base you type from 2 to 36. Press Copy beside any result.

  4. Fraction digits

    For fractional numbers choose how many digits to show. Repeating digits are put in brackets, and the tool tells you if a fraction was cut short.

  5. Two's complement

    The table shows the bit pattern and hex of the whole-number part in 8, 16, 32 and 64 bits, or says it does not fit. To decode a pattern, set "Read input as two's complement" to the width.

  6. See the working

    Choose the target base under Step-by-step working to see the place-value sum, the division table read bottom up, and the multiplication table for the fraction.

Worked example: 255.625 to binary

Whole part: 255 ÷ 2 = 127 remainder 1, 127 ÷ 2 = 63 r 1, and so on down to 1 ÷ 2 = 0 r 1. Reading the remainders from the bottom up gives 11111111. Fraction part: 0.625 × 2 = 1.25 (digit 1), 0.25 × 2 = 0.5 (digit 0), 0.5 × 2 = 1 (digit 1), and the fraction is now 0. So 255.625 = 11111111.101 in binary, FF.A in hex and 377.5 in octal.

Tips and tricks

  • Each hex digit is exactly four binary digits, so FF = 1111 1111.
  • Many decimal fractions, like 0.1, repeat forever in binary. That is why computers show tiny rounding errors.
  • In two's complement the top bit is the sign: 1000 0000 in 8 bits is −128.
  • Letters can be typed in upper or lower case: ff and FF are the same.
  • For base 36 the digits go up to Z, which is 35.

Problems and how to fix them

It says a digit is not allowed

Each base only uses digits below the base. Binary uses 0 and 1, octal 0 to 7. Check that the input base is set correctly.

The fraction ends with no brackets and a note

The digits did not end or repeat within the limit. Choose more fraction digits.

Two's complement says "Does not fit"

The number is outside the signed range for that width, for example 200 needs more than 8 signed bits.

Decoding a pattern gives an error

Two's complement input must be a whole, non-negative pattern with no more bits than the chosen width.

Questions and answers

Can it convert fractions?

Yes. The fractional part is converted exactly; repeating digits are shown in brackets, and very long results are cut at the number of digits you choose, with a note.

How are negative numbers handled?

With a minus sign in every base, plus a two's complement table for 8, 16, 32 and 64 bits.

Can I decode a two's complement pattern?

Yes. Set Read input as two's complement to the bit width, then type a pattern such as 11111111 or FF.

Is there a size limit?

Numbers with thousands of digits are converted exactly using big integers.

Does it understand 0x and 0b?

Yes. The prefixes 0x, 0b and 0o set the base automatically.
