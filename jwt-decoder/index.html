What is JWT Decoder?
The JWT Decoder turns a JSON Web Token into readable JSON. It splits the token into its header, payload and signature, colours each part, and explains the standard claims such as issuer, subject, audience, issued-at and expiry in plain words.
It is made for developers, testers and support teams working with login systems, APIs and single sign-on providers. A badge shows at a glance whether the token has expired or is not valid yet.
The token is decoded in your browser and never sent anywhere. The signature is shown but not verified, because that needs the secret or key that only the server should have.


What you can use it for
Debug login problems
See whether a token has expired or has the wrong audience or issuer.
Check permissions
Read roles and scopes in an access token to understand why a request was refused.
Learn how JWTs work
Load the example token to see how the three parts fit together.
Inspect tokens from identity providers
Read ID tokens and access tokens from your sign-in service.
Support and testing
Check what user, tenant or session a token belongs to.


Step-by-step tutorial: how to use JWT Decoder
  1. Paste the token
    Copy the token from a request header, cookie or app and paste it in the box. Bearer in front, quotes and line breaks are removed for you.
  2. Check the badge
    Green means not expired, red means expired, and amber means not valid yet or no expiry set.
  3. Look at the coloured token
    The header is red, the payload purple and the signature blue, separated by dots.
  4. Read the header and payload
    Both are shown as formatted JSON with colours. Press Copy to copy either one.
  5. Read the claims explained
    Each known claim gets a short description, and times like exp and iat are shown as dates in your time zone with "in 2 hours" or "3 days ago".
  6. Verify on your server
    Before trusting any data, verify the signature in your own code with the right key.

Worked example: an expired token
You paste a token from a failing API call. The badge reads "Expired 2 hours ago". The payload shows sub "u1" and exp 1767225600, and the claims table explains exp as Expires at with the date in your own time zone. The fix is to get a new token by signing in again or using the refresh token.


Tips and tricks
  • Times in JWTs are in seconds, not milliseconds; the tool warns you if exp looks like milliseconds.
  • If the decoder says a part is cut off, copy the token again; long tokens are easy to truncate.
  • Never put passwords or secrets in a JWT payload: anyone with the token can read it, as this tool shows.
  • Use short expiry times for access tokens and check exp on the server, not only in the app.
  • Treat tokens with alg none as invalid on your server.


Problems and how to fix them
It says a JWT has three parts
The token is incomplete or not a JWT. Make sure you copied all of it, including both dots.
The header could not be decoded
The first part is damaged or not Base64URL. Copy the token again from its source.
It shows expired but the app works
The app may refresh tokens automatically, or the device clock may be wrong. Check your computer's date and time.
The payload is shown as plain text
The payload is not JSON, which some systems use. The text is shown as it is.



Questions and answers


Does this check if the token is genuine?
No. It only decodes the token. Anyone can create a token with any content, so the signature must be verified on your server with the correct secret or public key before you trust the data.
Is it safe to paste a real token?
Decoding happens entirely in your browser and the token is not sent or stored. Still, a valid token works like a password until it expires, so avoid sharing it and prefer expired or test tokens.
Why does it say the token is encrypted?
Tokens with five parts are encrypted JWE tokens. Their header can be read, but the content needs the private key and cannot be decoded here.
What do exp, iat and nbf mean?
exp is when the token expires, iat when it was issued, and nbf the time before which it must not be accepted. They are Unix timestamps in seconds and are shown as dates in your time zone.
Which algorithms are recognised?
All common ones: HS256/384/512, RS256/384/512, PS256/384/512, ES256/384/512 and EdDSA. Tokens with alg none are flagged because they are not signed.
